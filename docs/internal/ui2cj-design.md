# UI2CJ — Qt Designer .ui → CJQT6 仓颉代码生成器

> 配套仓库：`https://gitcode.com/yuan_1992/CJQT6`（Qt6 版，v1.9.0+）
> 本文档描述 `tools/ui2cj` 的实际实现形态（生成独立可运行 `main()` 文件），
> 并以仓库 `src/` 实际导出名为唯一真相源。
> **不要参考** `Cangjie-TPC/CJQT`（Qt5.14.2）以及任何 CSDN / DevPress 文章——
> 它们混用 `QApplication.create()`、`QPushButton(win)` 构造传参、`button.connect{...}` 等旧 API，
> 在 CJQT6 上会编译失败。

---

## 1. 目标与非目标

### 1.1 目标
将 Qt Designer 保存的 `.ui`（XML，根 `<ui version="4.0">`）**静态翻译**为符合 CJQT6 风格的仓颉源码：
- 有 cjpm 工程时，输出可被 `cjpm build` 直接编译的 `src/main.cj`（或 `xxx_ui.cj`），**独立可运行**（含 `main()` 与事件循环）；
- **无 cjpm 工程时自动引导**：向上探测 CJQT6 库根，生成最小可运行工程（`cjpm.toml` + `src/main.cj` + `deploy_qt.ps1`），`cd` 后 `cjpm build && cjpm run` 即可出窗口；
- 无需在运行时依赖 `QUiLoader`。

### 1.2 非目标（明确不做）
- ❌ 不做运行时动态加载（那是 `QUiLoader` 的事，仓库已支持）
- ❌ 不做 `.cj → .ui` 反向生成
- ❌ 不为 Designer 里**未封装到 CJQT6 的控件**做兜底（静默跳过，见 §10）
- ❌ 不生成 `delete` / `close` 调用（内存管理由 CJQT6 封装类负责）
- ❌ 不处理自定义 `Q_OBJECT` 子类（roadmap 反方向清单明确禁止）
- ❌ 不承诺「可 import 的类库形态」：当前输出为独立可运行的 `main()` 文件（类封装形态见 §12 演进路径「模式二」）

## 2. 输入：`.ui` 文件固定格式

`.ui` 是 Qt Designer 输出的 XML，Schema 由 Qt 定义，格式固定。生成器只需解析以下节点：

| XML 节点 | 含义 | 出现位置 |
|---------|------|---------|
| `<ui version="4.0">` | 根元素，固定版本号 | 根 |
| `<class>Name</class>` | Designer 里的类名（当前仅作注释提示，未用于生成） | 根下 |
| `<widget class="Qxxx" name="objName">` | 控件实例 | 任意层级 |
| `<layout class="Qxxx" name="objName">` | 布局实例 | 控件或布局内 |
| `<property name="xxx"><type>val</type></property>` | 属性设置 | widget/layout 内 |
| `<item>` | 布局子项 | layout 内 |
| `<connections><connection>` | 信号槽连接 | 根下 |
| `<customwidget>` / `<customwidgets>` | 自定义控件声明 | 根下（本项目忽略） |

**类型标签**（`<property>` 的子节点）：
`string`、`bool`、`number`、`double`、`enum`、`rect`、`size`、`font`、`stylesheet`、`set`（flags 集合）。

## 3. 输出：仓颉源码形态

### 3.1 生成文件模板（真实产物）

输入 `ui2cj_demo.ui`（顶层 `<widget class="QWidget" name="Form">`）→ 实际输出（节选自 `examples/ui2cj_demo2/src/main.cj`，46 行完整可编译）：

```cangjie
package ui2cj_demo

// ===== Auto-generated by ui2cj — DO NOT EDIT BY HAND =====
// Source: ui2cj_demo.ui
// Build: cjpm build (requires CJQT6 + Qt6)

import cjqt6.core.*
import cjqt6.gui.*
import cjqt6.views.*
import cjqt6.widgets.*

main(): Int64 {
    let app = QApplication()

    let Form = QWidget()
    Form.setTitle("Form")
    let verticalLayout_4 = QVBoxLayout()
    let verticalLayout_3 = QVBoxLayout()
    let verticalLayout_2 = QVBoxLayout()
    let horizontalLayout_2 = QHBoxLayout()
    let label = QLabel()
    label.setText("TextLabel")
    horizontalLayout_2.addWidget(label.getPtr())
    let comboBox = QComboBox()
    horizontalLayout_2.addWidget(comboBox.getPtr())
    verticalLayout_2.addLayout(horizontalLayout_2.getPtr())
    // …（嵌套布局 / tableWidget 等略）…
    Form.setLayout(verticalLayout_4.getPtr())

    Form.show()
    let result = app.exec()
    return Int64(result)
}
```

要点：
- 输出是**独立可运行文件**：自带 `main(): Int64`、`QApplication()`、`.show()` 与 `app.exec()`；
- 控件用无参构造（`QPushButton()`）创建，`.getPtr()` 作为布局/父子参数；
- 布局对象独立创建（`QVBoxLayout()`），最后 `parent.setLayout(layout.getPtr())`；
- import 按实际用到控件自动合并（`cjqt6.core/gui/widgets/views/menu` 等）。

### 3.2 命名规则
- `<widget name="btnOk">` → 变量名 `btnOk`（保留 Designer 原名，**不强制改大小写**）；
- 非法字符（非字母/数字/下划线）→ `_`；首字符是数字 → 前缀 `_`；
- 同名冲突 → 追加序号 `_2`、`_3`…（`gUsedNames` 去重）；
- 布局变量名优先取 .ui 布局元素自身 `name` 属性（如 `verticalLayout_4`），缺失时派生为 `<parentVar>_layout`；
- 回调骨架名 = `on_<sender>_<信号名>`（顶层 `let` 绑定，见 §6）。

## 5. 属性转换规则

`<property name="xxx">` 的子标签 → 调用对应 setter。以下为 `gen.cj::handleProperty` 实际支持的属性（按控件类型分派）：

| 控件类型 | 支持的属性 → 生成调用 |
|---------|---------------------|
| 通用 | `windowTitle`→`setTitle(String)`；`enabled=false`→`setEnabled(false)`；`toolTip`/`statusTip`→`setToolTip(String)`；`styleSheet`→`setStyleSheet(String)`；`minimumSize`→`setMinimumSize(w,h)`；`maximumSize`→`setMaximumSize(w,h)` |
| `QPushButton`/`QToolButton` | `text`→`setText`；`checkable=true`→`setCheckable(true)`；`checked=true`→`setChecked(true)`；`default=true`→`setDefault(true)` |
| `QLabel` | `text`→`setText`；`alignment`→`setAlignment(对齐值)`；`wordWrap=true`→`setWordWrap(true)` |
| `QLineEdit` | `text`→`setText`；`placeholderText`→`setPlaceholder(String)`；`readOnly=true`→`setReadOnly(true)`；`echoMode=Password`→`setEchoMode(2)`；`maxLength`→`setMaxLength(Int64)`；`alignment`→`setAlignment` |
| `QTextEdit`/`QPlainTextEdit`/`QTextBrowser` | `html`/`plainText`→`setText(String)`；`readOnly=true`→`setReadOnly(true)` |
| `QCheckBox`/`QRadioButton` | `text`→`setText`；`checked=true`→`setChecked(true)` |
| `QSlider` | `orientation`→`setOrientation(Orientation.Horizontal.value()/...)`；`maximum`→`setRange(0,max)`；`value`→`setValue`；`singleStep`→`setSingleStep` |
| `QProgressBar` | `minimum`→`setRange(min,100)`；`maximum`→`setRange(0,max)`；`value`→`setValue` |
| `QSpinBox`/`QDoubleSpinBox` | `minimum`/`maximum`/`value`→`setMinimum/setMaximum/setValue`；`prefix`/`suffix`→`setPrefix/setSuffix(String)` |
| `QComboBox` | `currentIndex`（≠0 才生成）→`setCurrentIndex(Int64)`；`editable=true`→`setEditable(true)` |
| `QGroupBox` | `title`→`setTitle`；`checkable=true`→`setCheckable(true)` |
| `QTabWidget` | `currentIndex`→`setCurrentIndex(Int64)` |
| 布局属性 | `spacing`→`setSpacing`；`margin`→`setMargin` |
| 忽略 | `geometry`（由布局或绝对定位处理）、`font`（CJQT6 暂无通用 setFont） |

> 未知属性 → **静默跳过**（不阻断生成）。

### 5.1 对齐值映射（`alignValue`）
`.ui` 里 `Qt::AlignCenter` 等经 `getEnum` 去掉 `Qt::` 前缀后按此表映射为 16 进制值：

| Qt 枚举值 | 生成的数值 |
|-----------|-----------|
| `AlignLeft` | `0x0001` |
| `AlignRight` | `0x0002` |
| `AlignHCenter` | `0x0004` |
| `AlignTop` | `0x0020` |
| `AlignBottom` | `0x0040` |
| `AlignVCenter` | `0x0080` |
| `AlignCenter` | `0x0084` |
| 其它 | `0x0001` |

## 6. 信号槽转换规则

### 6.1 `<connections>` 翻译

`.ui` 片段：
```xml
<connection>
  <sender>btnOk</sender>
  <signal>clicked()</signal>
  <receiver>MainWindow</receiver>
  <slot>onBtnOkClicked()</slot>
</connection>
```

→ 生成**顶层 `let` 回调骨架** + 在 `main()` 内连接：
```cangjie
// 回调骨架（main 之前）：
let on_btnOk_clicked: VoidCallback = { =>
    // TODO: 处理 btnOk 的 clicked() 事件
}

// main() 内：
btnOk.setOnClick(on_btnOk_clicked)
```

### 6.2 信号 → setter 映射（`gen.cj::SIGNAL_MAP`）

| 信号签名 | CJQT6 连接 API | 回调类型 |
|---------|---------------|---------|
| `clicked()` | `setOnClick` | `VoidCallback` |
| `clicked(bool)` | `setOnClickedChecked` | `Int32Callback` |
| `toggled(bool)` | `setOnToggled` | `Int32Callback` |
| `textChanged(QString)` | `setOnTextChanged` | `CStringCallback` |
| `returnPressed()` | `setOnReturnPressed` | `VoidCallback` |
| `editingFinished()` | `setOnEditingFinished` | `VoidCallback` |
| `valueChanged(int)` | `setOnValueChanged` | `Int32Callback` |
| `valueChanged(double)` | `setOnValueChanged` | `Float64Callback` |
| `currentIndexChanged(int)` | `setOnCurrentIndexChanged` | `Int32Callback` |
| `currentTextChanged(QString)` | `setOnCurrentTextChanged` | `CStringCallback` |
| `stateChanged(int)` | `setOnStateChanged` | `Int32Callback` |
| `sliderMoved(int)` | `setOnSliderMoved` | `Int32Callback` |
| `activated(int)` | `setOnActivated` | `Int32Callback` |

> 说明：回调采用「顶层 `let` + 全局共享」模式（仓颉 `CFunc` 不能捕获局部变量），骨架生成在 `main()` 之前，函数体留 `// TODO` 供开发者填写业务逻辑。

### 6.3 不支持的信号
遇到映射表里没有的信号（如 `customSignal(int, QString)`）→ **静默跳过**（`continue`），不生成该连接、不报错。

## 7. 布局与父子关系

- 布局对象**无参构造**（`QVBoxLayout()`），独立创建后由 `parent.setLayout(layout.getPtr())` 挂载；
- `<item>` 子项按出现顺序调用：
  - 子项是 `<widget>` → `layout.addWidget(child.getPtr())`
  - 子项是 `<layout>` → `layout.addLayout(childLayout.getPtr())`
  - `gridlayout` 子项带 `row`/`column`/`rowspan`/`colspan` → `addWidget(ptr, row, col[, rowspan, colspan])`
  - `formlayout` → 每行成对 `addRowWidget(ptr, ptr)`，单字段行 `addRow("", ptr)`
  - 子项含 `<spacer>` → `layout.addStretch()`
- `QMainWindow` 顶层：`centralwidget` → `setCentralWidget(ptr)`；`menubar` → `setMenuBar(ptr)`；`statusbar` → `setStatusBar(ptr)`；
- 无布局时退化为**绝对定位**：子控件 `setWidgetGeometry(ptr, x, y, w, h)` + `setWidgetParent(ptr, parentPtr)`。

## 8. 项目结构（实际）

```
CJQT6/
└── tools/
    └── ui2cj/                 ← 独立仓颉工具项目（纯仓颉，零第三方依赖）
        ├── cjpm.toml
        ├── README.md
        └── src/
            ├── main.cj        # CLI 入口：参数解析、cjpm 工程探测、无工程引导、写 deploy_qt.ps1
            ├── gen.cj         # 映射表（控件/布局/信号/对齐）+ 属性处理 + 布局/信号/顶层窗口生成
            └── xml_parser.cj  # 自研轻量 XML 解析器（XmlNode + parseXml）
```

### 8.1 CLI 用法
```bash
cd tools/ui2cj
cjpm build

# 基本：把 .ui 翻译成 .cj
cjpm run -- form.ui

# 指定输出文件
cjpm run -- form.ui out.cj

# 指定包名（首行生成 package 声明）
cjpm run -- form.ui --package demo

# 指定工程目录（向上探测的起点）
cjpm run -- form.ui --project-dir .

# 显式输出路径
cjpm run -- form.ui --output src/main.cj
```

参数约定（`main.cj`）：
- `--package <name>` / `--project-dir <dir>` / `--output <file>` 三个具名选项，其余按位置参数处理；
- 无工程时：自动生成最小可运行工程（见 §8.2）；
- 输出默认规则：工程根有 `src/` 目录时输出 `src/main.cj`，否则输出 `<base>_ui.cj`。

### 8.2 无 cjpm 工程自动引导（本次核心能力）

`main()` 里 `findProjectAndRepo(startDir)` 从 `.ui` 所在目录**向上**逐级查找 `cjpm.toml`，读取 `[package] name`：

- 命中**普通工程**（包名 ≠ `cjqt6`）→ 复用其包名，输出到其 `src/main.cj` 或 `<base>_ui.cj`；
- 命中**库自身工程**（包名 `cjqt6`，即仓库根）→ 视为「无用户工程」，记下库根后继续向上；
- 最终无工程且定位到库根 → 调用 `writeScaffoldProject` 生成最小可运行工程：
  - `cjpm.toml`：`output-type = "executable"`，`link-option = "-L../../releases/windows-x64 -lcjqt6_bridge"`，依赖 `cjqt6 = { path = "../../" }`；
  - `src/main.cj`：转换结果；
  - **`deploy_qt.ps1`**：部署 Qt6 bin DLL + platforms/styles/imageformats 插件 + MSVC 运行库 + cjqt6 依赖 DLL + `cjqt6_bridge.dll`，脚本**前置 UTF-8 BOM**——Windows PowerShell 5.1 对无 BOM UTF-8 按 ANSI 解析，中文多字节会错位吞掉行尾引号导致语法错误，加 BOM 后 `powershell -ExecutionPolicy Bypass -File deploy_qt.ps1` 可正常解析执行；
- 未定位到库根 → 输出独立 `.cj` 文件并提示用 `--project-dir` 指定。

> 注意：`findProjectAndRepo` 用相对路径向上时 `Path.parent` 最终会返回空串，`join` 抛异常——实现里已对空 parent 做终止守卫。

## 9. 核心数据结构（实际）

```cangjie
// xml_parser.cj —— 自研轻量 XML 解析器
public class XmlNode {
    public var tag: String
    public var attrs: HashMap<String, String>
    public var children: ArrayList<XmlNode>
    public var text: String
    public func attr(name: String): String          // 读属性
    public func findChild(tagName: String): ?XmlNode
    public func findChildren(tagName: String): ArrayList<XmlNode>
}
public func parseXml(src: String): XmlNode

// gen.cj —— 映射表（模块级全局 var，initMaps 时重建）
var WIDGET_MAP: HashMap<String, String>    // Qt 类名 → CJQT6 类
var WIDGET_MOD: HashMap<String, String>    // Qt 类名 → 所在包

var SIGNAL_MAP: HashMap<String, (String, String)>  // 信号签名 → (setter, 回调类型)

// gen.cj —— 回调信息（信号连接骨架）
public class CallbackInfo {
    public var varName: String
    public var cbType: String
    public var sender: String
    public var signal: String
}
```

## 10. 错误处理策略（实际行为）

| 情况 | 实际行为 |
|------|---------|
| `.ui` 文件不存在 | `main()` 提示「文件不存在」并返回 |
| `.ui` 里没有 `<widget>` | 抛异常 `Invalid .ui file: no <widget> found` |
| 顶层控件类不在 §4 映射表 | 抛异常 `Unsupported top-level widget: <type>` |
| 子控件类不在 §4 映射表 | **静默跳过**（`continue`），不报错 |
| 属性不在 §5 支持列表 | **静默跳过** |
| 信号不在 §6.2 映射表 | **静默跳过**（不生成该连接） |
| XML 解析失败 | 抛异常（`parseXml`） |

> 提示：`main()` 调用 `generate()` 外包了 `try/catch`，失败时打印 `[FAIL] 转换失败：<message>`。

## 11. 与仓库 roadmap 的衔接

roadmap §6.1「Designer → 仓颉代码流水线」原文：
> 写一个仓颉工具（解析 `.ui` XML → 生成 `import cjqt6.*` 的布局+信号连接代码）；
> 依赖仓颉 `std.json`/`std.ast` 或直接字符串处理即可，无需 C++。

本文档是该条目的落地实现，已标 ✅（2026-08-10）：
- ✅ 纯仓颉实现，零 C++ 改动，零第三方依赖（自研轻量 XML 解析器）
- ✅ 输出严格使用 CJQT6 真实 API（`QApplication()`、`setTitle`、`getPtr()`、`setOnClick` 等）
- ✅ 不依赖运行时反射（仓颉无反射，roadmap 已确认）
- ✅ 输出文件可直接被 `cjpm build` 编译进业务项目，且是独立可运行文件
- ✅ 无工程自动引导：生成最小可运行工程 + `deploy_qt.ps1`（UTF-8 BOM，兼容 PowerShell 5.1）

## 12. 演进路径（建议顺序）

1. **已实现（MVP 及以上）**：控件/布局/属性/信号生成、import 自动合并、命名去重、顶层 QMainWindow 组装、无工程自动引导 + deploy_qt.ps1、绝对定位兜底、grid/form 布局行号。
